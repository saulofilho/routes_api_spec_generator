The problem

Swagger as input breaks rswag

Avoid

OpenAPI → spec

In projects using rswag:specs:swaggerize, the contract is the output of specs. Generating tests from Swagger creates a circular dependency for new endpoints.

This gem

Routes → spec → swagger

The source of truth is config/routes.rb and your controllers. The gem generates rswag boilerplate; you refine mocks and schemas; swagger comes from the tests.

How it works

A 4-step pipeline

  1. 01

    Collect routes

    Filters endpoints under a namespace (e.g. /api/v1) via Rails.application.routes.

  2. 02

    Inspect controllers

    Infers services, tenant header, parameters, and ERB template from code patterns.

  3. 03

    Merge YAML

    Optional overrides in config/routes_api_spec_generator.yml keyed by controller#action.

  4. 04

    Write specs

    Materializes spec/requests/**/_spec.rb ready for rspec and swaggerize.

What you get

Less boilerplate, more coverage

🛤️

Route collector

Discovers GETs (and other configurable verbs) under an API prefix.

Core
🔍

Controller inspector

Regex over source code for services, tenant, and domain templates.

  • Insights, channels, big numbers
  • Headers Tenant-ID / X-Tenant-ID
  • Params start_date, end_date
📄

ERB templates

rswag specs with path, parameter, response, and base mocks.

⚙️

CLI + Rake

routes-api-spec-generator or rake routes_api_spec:generate in your Rails app.

📝

YAML overrides

Tune tag, summary, service_class, and template without changing the gem.

🚫

Safe by default

Does not overwrite existing specs — use FORCE=true to regenerate.

When to use

The right moments

  • ✓
    New endpoint on a Rails API Generate the base request spec before writing detailed mocks and schemas.
  • ✓
    Projects with rswag (spec → swagger) Keeps the correct cycle without reading the OpenAPI contract as input.
  • ✓
    Greenfield or coverage gaps Bootstrap several endpoints at once from real routes.
  • ✓
    Standardize request specs Same structure for path, headers, query params, and 400 responses.

Ruby gem

Install and generate your specs

Works with any Rails app using rswag. Templates customizable via YAML.

Gemfile
gem 'routes_api_spec_generator'
Install
gem install routes_api_spec_generator
Generate specs
bundle exec rake routes_api_spec:generate
Force overwrite
FORCE=true bundle exec rake routes_api_spec:generate
Generate
routes-api-spec-generator generate
With options
routes-api-spec-generator generate --force --namespace /api/v1
config/routes_api_spec_generator.yml
endpoints: api/v1/insights#email_metrics: template: insights tag: Insights tenant_header: X-Tenant-ID service_class: Insights::EmailService channel: email
