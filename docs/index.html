O problema

Swagger como entrada quebra no rswag

Evitar

OpenAPI → spec

Em projetos com rswag:specs:swaggerize, o contrato é saída dos specs. Gerar testes a partir do Swagger cria dependência circular para endpoints novos.

Esta gem

Rotas → spec → swagger

A fonte de verdade são config/routes.rb e os controllers. A gem gera o boilerplate rswag; você refina mocks e schemas; o swagger nasce dos testes.

Como funciona

Pipeline em 4 passos

  1. 01

    Coleta rotas

    Filtra endpoints do namespace (ex.: /api/v1) via Rails.application.routes.

  2. 02

    Inspeciona controllers

    Infere services, tenant header, parâmetros e template ERB por padrão de código.

  3. 03

    Merge com YAML

    Overrides opcionais em config/routes_api_spec_generator.yml por controller#action.

  4. 04

    Grava specs

    Materializa spec/requests/**/_spec.rb prontos para rspec e swaggerize.

O que entrega

Menos boilerplate, mais cobertura

🛤️

Route collector

Descobre GETs (e outros verbos configuráveis) sob um prefixo de API.

Core
🔍

Controller inspector

Regex sobre o código-fonte para services, tenant e templates por domínio.

  • Insights, channels, big numbers
  • Headers Tenant-ID / X-Tenant-ID
  • Parâmetros start_date, end_date
📄

Templates ERB

Specs rswag com path, parameter, response e mocks base.

⚙️

CLI + Rake

routes-api-spec-generator ou rake routes_api_spec:generate no app Rails.

📝

YAML overrides

Ajuste tag, summary, service_class e template sem alterar a gem.

🚫

Safe by default

Não sobrescreve specs existentes — use FORCE=true quando quiser regenerar.

Quando usar

Momentos certos

  • ✓
    Novo endpoint na API Rails Gere o request spec base antes de escrever mocks e schemas detalhados.
  • ✓
    Projeto com rswag (spec → swagger) Mantém o ciclo correto sem tentar ler o contrato OpenAPI como entrada.
  • ✓
    Greenfield ou gap de cobertura Bootstrap de vários endpoints de uma vez a partir das rotas reais.
  • ✓
    Padronizar request specs Mesma estrutura de path, headers, query params e respostas 400.

Ruby gem

Instale e gere seus specs

Funciona em qualquer app Rails com rswag. Templates customizáveis via YAML.

Gemfile
gem 'routes_api_spec_generator'
Instalar
gem install routes_api_spec_generator
Gerar specs
bundle exec rake routes_api_spec:generate
Forçar overwrite
FORCE=true bundle exec rake routes_api_spec:generate
Gerar
routes-api-spec-generator generate
Com opções
routes-api-spec-generator generate --force --namespace /api/v1
config/routes_api_spec_generator.yml
endpoints: api/v1/insights#email_metrics: template: insights tag: Insights tenant_header: X-Tenant-ID service_class: Insights::EmailService channel: email
